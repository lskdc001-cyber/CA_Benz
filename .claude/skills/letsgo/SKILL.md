# 레츠고

사용자가 `레츠고`라고 하면, **직전에 내가 추천한 다음 단계를 다시 설명하게 하지 않고 그대로 실행한다.**

이 스킬이 존재하는 이유는 단순하다. 작업이 끝날 때마다 나는 다음 단계를 추천하는데, 사용자가 그중 하나를 고르려면 그 내용을 다시 타이핑해야 한다. 그 마찰을 없애는 것이 목적이다. 그러니 **되묻지 말고 실행하는 것이 기본값**이다.

## 1. 무엇을 실행할지 결정한다

우선순위대로 찾는다.

**① 대화 안에 추천이 있는 경우 (대부분)**
직전 내 발언에서 "다음 단계", "제안", "~할까요?", "~하는 것을 권합니다" 형태로 제시한 항목을 찾는다. 가장 최근 것이 대상이다.

여러 개를 나열했다면:
- `(Recommended)` 표시나 "권합니다", "우선" 같은 표현으로 내가 이미 우선순위를 매겼다면 그것
- 우선순위 표시가 없으면 목록의 첫 번째

**② 사용자가 특정 항목을 지목한 경우**
`레츠고 2` → 목록의 2번. `레츠고 API 연동` → 그 내용과 가장 가까운 항목. 지목이 있으면 우선순위 규칙보다 지목이 이긴다.

**③ 대화에 추천이 없는 경우 (새 세션 등)**
저장소 상태에서 다음 할 일을 복원한다. 이 프로젝트라면 이런 것들을 본다:
- `README.md`의 "알려진 제약 / 다음 단계"
- `docs/PLANNING.md`의 로드맵에서 아직 미완인 Phase
- 열려 있는 PR의 미해결 리뷰·CI 상태
- 최근 커밋 이후 자연스럽게 이어지는 작업

복원한 결과가 확실하지 않으면, 후보 2~3개를 짧게 제시하고 고르게 한다. 이때만 되묻는다.

## 2. 실행 전에 한 줄로 선언한다

허락을 구하는 게 아니라, 내가 엉뚱한 걸 집었을 때 사용자가 즉시 멈출 수 있게 하기 위함이다. 길게 쓰지 않는다.

```
레츠고 → "CRM 리드 등록 폼에 수신동의 체크 추가" 진행합니다.
```

그리고 바로 작업을 시작한다. 확인 응답을 기다리지 않는다.

## 3. 끝까지 진행한다

추천했던 범위를 그대로 완수한다. 코드 작업이라면 이 프로젝트의 평소 흐름을 따른다:

1. 구현
2. `npx next build`로 타입·빌드 검증
3. 동작 확인 (필요하면 `npx next start` 후 curl로 실제 응답 확인)
4. 커밋 + 지정 브랜치로 푸시

작업 도중 추천 내용에 없던 문제를 발견하면, 그 자리에서 범위를 임의로 넓히지 말고 완료 후 보고에 적는다.

## 4. 예외 — 이때는 먼저 확인한다

되돌리기 어렵거나 외부로 나가는 작업은 `레츠고`만으로 실행하지 않는다. 사용자가 `레츠고`로 위임한 것은 "다시 설명하는 수고"이지 "확인 절차" 자체가 아니기 때문이다.

- 실제 고객에게 메시지·이메일 발송
- 프로덕션 배포, 외부 서비스 공개
- PR 머지, 브랜치·파일 삭제, 히스토리 되감기
- 비용이 실제로 청구되는 작업

이런 항목이 걸리면 무엇을 하려는지와 영향 범위를 한두 줄로 말하고 확인을 받는다. 확인만 받으면 되니, 계획을 처음부터 다시 설명할 필요는 없다.

## 5. 끝나면 다음 단계를 다시 추천한다

이게 이 스킬의 핵심 루프다. 작업을 마칠 때마다 다음에 할 만한 것을 다시 제시해야 사용자가 또 `레츠고`만으로 이어갈 수 있다.

추천은 구체적으로 쓴다. "테스트를 추가하세요"보다 "팔로업 차단 로직에 단위 테스트를 붙이면 날짜 경계 버그를 잡을 수 있습니다"처럼, 왜 그게 지금 할 만한지가 드러나야 사용자가 고를 수 있다.

여러 개를 제시할 때는 번호를 붙인다. 그래야 `레츠고 3`가 가능해진다.
